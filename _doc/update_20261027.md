# free-fs SeaweedFS 接入方案

- 日期：2026-10-27
- 状态：方案已确定，尚未开始实现
- 目标：为 free-fs 接入 SeaweedFS 单机 S3 后端，保持浏览器 HTTPS 直链只访问 free-fs 后端

## 1. 结论

选择 **SeaweedFS 4.51 + `weed mini` 单机模式**，替代 Apache Ozone 方案。

同时采用 **方案 C**：

- SeaweedFS S3 仅在内网提供，不暴露给浏览器。
- 新增 free-fs 原始文件流接口 `/api/file/stream/raw/{fileId}`。
- `getFileUrl` 对 SeaweedFS 返回带签名 token 的 raw 接口 URL，保证返回原始文件字节。

## 2. 为什么选择 SeaweedFS

| 维度 | Ozone 2.2.1 all-in-one | SeaweedFS 4.51 `weed mini` |
|---|---|---|
| 单机部署 | 组件多，需要初始化 volume/bucket | 一个容器、一个进程，自动启动 master/volume/filer/S3 |
| 凭据与 bucket | 需手动配置 | 环境变量自动写入凭据并预创建 bucket |
| 单节点副本 | 需确保 replication=ONE，存在 storageClass 风险 | 默认 `000`，无 storageClass/THREE 问题 |
| S3 兼容性 | 核心 API 够用，但 CORS/ACL/Policy/Versioning 较弱 | CopyObject、Range、Multipart、ListV2、CORS、ACL、Policy、Versioning、预签名均支持 |
| 资源占用 | JVM + 多组件，较重 | Go 单进程，轻量 |
| 适用场景 | Hadoop/Ozone 生态、多节点 HA | 单机 S3、POC、小规模部署 |

当前项目是单机 POC，无历史数据迁移，只需要 S3 能力，因此 SeaweedFS 更合适。

## 3. 目标架构

```text
浏览器 HTTPS
  -> free-fs 后端 /api/file/stream/raw/{fileId}?token=...
  -> free-fs server
  -> http://free-fs-seaweedfs:8333  (Docker 内网)
```

安全边界：

- SeaweedFS 的 `8333` 只 `expose` 到 Docker 网络，不发布到宿主机。
- 浏览器只能访问 free-fs 的 HTTPS 接口。
- SeaweedFS 管理操作通过 `docker exec` + `weed shell`，不暴露 Admin UI。
- raw 接口使用签名 token 鉴权，token 绑定 fileId 和 workspaceId，并设置过期时间。

## 4. SeaweedFS 部署

在 `../docker/docker-compose.yml` 增加：

```yaml
free-fs-seaweedfs:
  image: chrislusf/seaweedfs:4.51
  container_name: free-fs-seaweedfs
  restart: unless-stopped
  environment:
    AWS_ACCESS_KEY_ID: ${SEAWEEDFS_ACCESS_KEY:-freefs}
    AWS_SECRET_ACCESS_KEY: ${SEAWEEDFS_SECRET_KEY:?set SEAWEEDFS_SECRET_KEY}
    S3_BUCKET: free-fs
    TZ: Asia/Shanghai
  volumes:
    - ./seaweedfs/data:/data
  expose:
    - "8333"
```

说明：

- 镜像默认命令是 `mini -dir=/data`，无需覆盖 `command`。
- `S3_BUCKET=free-fs` 首次启动自动建桶，重复启动幂等。
- `AWS_ACCESS_KEY_ID` / `AWS_SECRET_ACCESS_KEY` 首次启动写入 SeaweedFS 凭据。
- 不设置凭据时 SeaweedFS 进入 **Allow All** 模式，生产/POC 必须显式设置。
- 首次启动后凭据写入 filer，后续以 filer 中配置为准。
- 管理 bucket：

```bash
docker exec -it free-fs-seaweedfs weed shell
# 然后执行
s3.bucket.list
```

- 可选加固，关闭不需要的 WebDAV/Admin/Iceberg/Lance：

```yaml
command: ["mini", "-dir=/data", "-webdav=false", "-admin.ui=false", "-s3.port.iceberg=0", "-s3.port.lance=0"]
```

- `../.gitignore` 增加：

```text
docker/seaweedfs/data/
```

- 如果 free-fs server 不在同一 Docker 网络，可临时发布 `127.0.0.1:8333:8333` 调试，但仍不暴露给浏览器。
- 数据备份：备份 `docker/seaweedfs/data` 或对应数据卷。单机模式无副本，不做备份会有数据丢失风险。

## 6. 新增 raw 文件流接口

在 `FileStreamController` 增加：

```text
GET/HEAD /api/file/stream/raw/{fileId}?token=...
```

行为：

- 不经过 `PreviewStrategy`，永远返回原始文件字节。
- 与现有 `/api/file/stream/preview/{fileId}` 分离：
  - preview：Office 文件转 PDF，供预览页使用。
  - raw：保留原始 docx/pptx 等文件，供 `getFileUrl` 和下载使用。
- 只支持单个 Range：
  - `bytes=0-`
  - `bytes=100-200`
  - `bytes=-500`
- 非法 Range、多段 Range、start 超出文件大小：返回 `416`，带 `Content-Range: bytes */size`。
- 不应用 `previewConfig.getMaxRangeSize()` 截断；raw 用于完整下载和视频拖动。
- 响应头：
  - `Content-Type`：优先 `fileInfo.getMimeType()`，其次按文件名推断，最后 `application/octet-stream`
  - `Content-Length`：完整文件长度或 Range 长度
  - `Content-Range`：Range 请求时设置
  - `Accept-Ranges: bytes`
  - `Content-Disposition: inline; filename*=UTF-8''...`
  - `X-Content-Type-Options: nosniff`
  - `Cache-Control: private, max-age=0, must-revalidate`
- `?download=1` 时改为 `Content-Disposition: attachment`。
- `HEAD` 返回相同的响应头，但不打开存储流。
- 文件不存在、已删除、是目录、跨工作空间：返回 `404`。
- 日志不打印 token。

实现位置：

- `FileStreamController` 复用现有 `copyStream()` / `copyStreamLimited()`。
- 新增 Range 解析辅助方法，建议使用 Spring `HttpRange`。
- 不修改现有 preview 方法的行为。

## 7. raw URL 签名与拦截器

新增 `RawFileTokenService`：

- `issue(fileId, workspaceId, ttlSeconds)` 生成 32 位 hex token。
- Redis 保存：
  - `fs:file:raw:token:{token}` -> `fileId`
  - `fs:file:raw:workspace:{token}` -> `workspaceId`
- TTL：
  - 优先使用 `expireSeconds`。
  - 默认 `3600` 秒。
  - 最长建议 `604800` 秒（7 天）。
- `resolve(token)` 返回 `fileId + workspaceId`。
- token 不消费，支持视频 Range 多次请求。
- 新增 `RawFileInterceptor`：
  - 只拦截 `/api/file/stream/raw/**`
  - 校验 token 与路径中的 fileId 匹配
  - 从 token 恢复 `WorkspaceContext`
  - 失败返回 `403`
  - `afterCompletion` 清理 `WorkspaceContext`
- 在 `WebMvcConfig` 注册，`order(4)`。
- 不要给 raw 路径添加 Sa-Token 登录拦截；token 即鉴权。

RedisKey 增加：

- `FILE_RAW_TOKEN_KEY = "file:raw:token"`
- `FILE_RAW_WORKSPACE_KEY = "file:raw:workspace"`
- `getFileRawTokenKey(String token)`
- `getFileRawWorkspaceKey(String token)`

## 8. 修改 getFileUrl

`FileInfoServiceImpl.getFileUrl()` 增加能力分支：

```text
if (storageService.supportsBrowserDirectUrl()) {
    return storageService.getFileUrl(objectKey, expireSeconds);
}
return "/api/file/stream/raw/" + fileId + "?token=" + rawFileTokenService.issue(...);
```

`IStorageOperationService` 增加默认方法：

```java
default boolean supportsBrowserDirectUrl() {
    return true;
}
```

行为：

- SeaweedFS 覆盖为 `false`。
- 现有 MinIO/RustFS/Local 等插件默认 `true`，行为不变。
- SeaweedFS 的 `getFileUrl` 返回：

```text
/api/file/stream/raw/{fileId}?token=...
```

- `expireSeconds` 为空时默认 1 小时，与现有 S3 预签名默认一致。
- 返回相对 URL，浏览器按当前 HTTPS 源解析，避免 Docker 内部地址和反向代理 host 问题。
- 前端当前没有调用 `getFileUrl`，因此不需要修改前端。
- `fillThumbnailUrl()` 继续返回 `/api/file/stream/preview/{fileId}`，不变。
- `PreviewService` 和 Office 预览继续走 `/preview`，不变。

## 9. S3 兼容性修复

### 9.1 HeadObject 404

`AbstractS3CompatibleStorageService.isFileExist()` 目前只捕获 `NoSuchKeyException`。SeaweedFS 的 `HeadObject` 缺失对象可能返回 `S3Exception` 404，需兼容：

- 捕获 `S3Exception`。
- `statusCode == 404` 且不是 `NoSuchBucket` 时返回 `false`。
- 其他错误继续抛出 `StorageOperationException`。
- 避免把 bucket 不存在误判为文件不存在。

### 9.2 CopyObject 大文件

`rename()` 使用 S3 `CopyObject` + `DeleteObject`。

- SeaweedFS 支持 CopyObject。
- S3 CopyObject 单次上限 5GB。
- free-fs 当前未实现 multipart copy，>5GB 文件重命名仍是已知限制。
- POC 至少验证普通大文件；如果业务需要 >5GB 重命名，再补 multipart copy。

### 9.3 uploadFile 的 Content-Length

`AbstractS3CompatibleStorageService.uploadFile()` 使用 `inputStream.available()` 作为 Content-Length。

- 对 `FileInputStream` 通常可用。
- 对网络流/包装流可能不可靠，存在截断风险。
- POC 验证上传完整性；如果发现截断，改为显式 content length 或先落临时文件。

## 11. 已知限制与风险

- SeaweedFS `weed mini` 是单机模式，无副本；必须备份 `/data`。
- `mini` 同时启动 WebDAV/Admin/Iceberg/Lance 等服务；不发布端口即可，建议关闭不需要的服务。
- SeaweedFS 未配置 scoped IAM 时使用 admin 凭据；POC 可接受，生产建议 `s3.json` + bucket owner。
- raw URL 是 bearer token，拿到 URL 即可在有效期内访问；不要写入日志或公开分享。
- S3 CopyObject 5GB 限制。
- `uploadFile()` 的 `available()` Content-Length 风险。
- `getFileUrl` 返回相对 URL；如果 API 客户端要求绝对 URL，需要在网关或调用方拼接。

## 12. 待确认

当前方案按以下默认设计记录：

1. raw URL 使用**签名 token**，不是登录 cookie。
2. raw URL 返回**相对路径**，不是绝对 URL。
3. `Content-Disposition` 默认 **inline**，`?download=1` 时 attachment。
4. token 默认 TTL **1 小时**，可通过 `expireSeconds` 调整。

如果以上默认项需要调整，在实现前修改本方案。
